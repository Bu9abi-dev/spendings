Spending tracker: council verdict

The question: what should v1 be, where should the data live, and how should Apple Pay logging work?

Recommendation

Build an iOS Shortcut that logs each Apple Pay payment as it happens and writes it straight to the Google Sheet, which holds the record. Pair it with a no-build web app that leads with AED left this month. Charts come second. Include transfers, merchant memory and card "envelopes". Protect the sync with a token, dedupe, locking and formula sanitising.

First step: on the real iPhone, set up a Wallet automation that only shows the Amount, Merchant and Card it receives. Pay once with each card and check what iOS actually provides.

The peer review settled it: opening a URL from a Shortcut lands in Safari, not the home-screen app, and the two have separate storage.

Where the council agrees

  • The Apple Pay moment is the product. Trackers die in week two.
  • Use one Ledger tab as the record and generate the monthly tabs from it.
  • Add Transfer as a third type next to income and spending.
  • Learn each merchant's category; cards act as envelopes (ADCB allowance left, warn on ADIB use).
  • Use Liquid Glass only on the nav and sheets. Cut AI, OCR and gamification.

Blind spots caught in peer review

  • A secret baked into public JavaScript isn't secret. Enter it once on the device.
  • Duplicate triggers. Dedupe with a deterministic id.
  • Merchant names that start with “=” become live formulas in the Sheet.
  • Failures when offline at the till. Show a failure notification and a reconcile nudge.
  • “Ask Before Running” must be off. Add an app lock and a backup/export.
  • Setup is the real product. Avoid a build step the owner can't debug.
Contrarian

Fatal flaw: Open URL opens Safari, so local-first loses data. The Shortcut should do everything and POST to the Sheet. Make sure BOTIM is in Wallet. Add Transfers, a token and LockService. Use one Ledger tab and keep glass light.

First Principles

The real problem is getting each payment logged. Capture first and categorise later. An uncategorised row is still true. The Sheet holds the record. Generate the monthly tabs. Add card-purpose meaning and an ADCB burn-down.

Expansionist

Capture with zero taps and keep an inbox. Learn categories from merchants. Treat cards as envelopes. Add UAE touches: AED, and optionally salary-cycle months. Put a lock-screen glance on a Shortcut. Later: bank SMS/email ingestion.

Outsider

“Prompted” only means a banner. Make setup one tap and include a test transaction. Handle transfers, refunds and splits. The daily question is “how much allowance is left”. Wallet card names need mapping.

Executor

Build the riskiest part first: the Apps Script, then the automation on the real phone. Use client UUIDs. Watch the Pages base path and the manifest scope. Auto-suggest the category from the merchant.
